# V3 知识库系统 2.0：从「内置大纲」到「用户共建」

> 状态：方案定稿（2026-10-05），未开始实施。是 `V3_PLAN.md` 的知识库专项。
> 范式转变：agent 定位从「考研数学错题本」→「考研学习 / 日常学习伴侣」（D16），
> 知识库从「AI 一步建好、App 只读消费」的 768 考点数学树，变为
> **AI 只搭骨架、用户逐步构建/完善/整理/规划的通用学习知识库**。

---

## 0. 范式对照

| | 旧（V2 现状） | 新（V3 知识库 2.0） |
|---|---|---|
| 建库者 | 开发期 AI 一次性生成 JSON 资产 | **用户**在向导帮助下逐节共建 |
| AI 的角色 | 无（数据是预制好的） | 搭骨架（建库向导）、当助手（补全/梳理**建议**）、做推荐（下一步学什么） |
| 学科 | 考研数学（math1/2/3 硬编码） | 任意学科：考研四科/公考/语言/技能，一个学科一棵树 |
| 内容 | 结构化字段（定义/公式/陷阱），只读 | 自由 Markdown，用户写自己的话；AI 补全只是**草稿** |
| 考研字段 | exam_weight / exam_years 内建 | 降级为普通 frontmatter 字段与正文小节——数学树的特性，不是系统的特性 |

**不动摇**：Markdown 事实源、本地优先、BYOK、先量再改；
**AI 对盘面的任何修改必须经用户确认后才落盘**（骨架落盘、补全草稿、梳理 diff 三处全部如此）。

## 1. 数据模型（D13：每节点一个 md，文件夹=章节）

```
<库根>/knowledge/
  kao-yan-shu-ju-jie-gou/            # 一个学科一棵树
    _subject.md                      # 学科节点：目标/考试日期/教材（frontmatter）
    01-绪论/
      01-1 什么是数据结构.md
      01-2 算法分析.md
    02-线性表/
      02-1 顺序表.md
      02-1 顺序表/                   # 子级目录（可选，层级无硬上限）
        02-1.1 静态分配.md
```

**节点文件 frontmatter**（解析宽容，坏字段如实上报 failures——与 problems 同纪律）：

```yaml
id: kn-7f3a2c            # 生成后永不改变——重命名/移动文件都不动它
name: 顺序表
aliases: [顺序存储, sequential list]
tags: [数据结构, 线性表]
deps: [kn-1a2b3d]        # 前置知识节点（D15）
priority: 2              # 0–3，规划用
status: skeleton | draft | filled | reviewed
source: seed | ai | user
created_at: 2026-10-05
updated_at: 2026-10-05
```

**正文 = 自由 Markdown**（统一走 `MathRendering` 渲染 LaTeX）。仅保留**惯例小节**（不强制、缺了不报错）：
`## 定义`、`## 公式`、`## 陷阱`、`## 考频（估算）`、`## 自己的话`、`## 来自 <课时> 的笔记`。
AI 补全的内容一律先以 `## AI 草稿（待确认）` 小节追加，用户改写确认后去标记转正——"草稿"与"已采纳"在文件上永远可分辨。

**派生索引**（镜像 `problems_index` 全套管线：Isolate 扫描 / mtime 增量 / idConflicts 上报 / selectOnly 列裁剪）：

- `knowledge_index`：id / subject_id / parent_id / name / path / level / status / priority / aliases / mtime
- `knowledge_fts`：FTS5 外部内容表，索引正文（搜"特征值"能命中用户自己的话）

**id 稳定性规则**：重命名文件、拖拽移动、改标题都不产生新 id；只有"删除再新建"才是新节点。
index 重建时发现同 id 两文件 → idConflicts 如实上报，不静默覆盖。

**内置数学树迁移（D14）**：math1/2/3 JSON 一键导入为可编辑学科，**节点 id 原样保留**
（`math1.linalg.eigen` 这类语义 id 不换）——存量题目挂的考点关联、掌握度数据全部继续有效。
考研专用字段迁移映射：`exam_weight` → `priority`（≥0.85→3，≥0.6→2，其余→1），
`exam_years`/`typical_qtypes` → 正文 `## 考频（估算）` 小节（估算值标注一并带过去）。
JSON 资产**不删**，降级为"新装机可选种子模板"，importer 常驻。

## 2. 建库向导：AI 只搭骨架（一次性动作，替代"AI 一步建库"）

三个起点，产物相同：**一棵只有目录和空位的树**（每节点：名称 + 一句话简介 + 惯例空小节 + `status: skeleton`）。

1. **空白建库**：输入学科名 + 目标（"考研 408，2027 考"）+ 可选教材名 →
   GLM 文本模型生成三级骨架（章节/节/知识点，deps 建议一并给出）→
   树编辑器里增删改调 → 确认后一次性落盘。
   **Prompt 纪律：只出目录和"该记什么"的空位，绝不写内容**——骨架的价值是"该学什么"的完整清单。
2. **拍目录**：复用 P1 视觉管道——教材目录页/讲义 PPT 拍照 → 章节骨架。
   （与 StudyMate 的 syllabus 同思路，但产物是知识树，不是任务清单。）
3. **种子导入**：内置数学树一键转换（见 §1）。

向导跑完 AI 就退场——后续每一步内容都由用户主导（写、导入笔记、或主动点"AI 补全"）。

## 3. 树编辑器：逐步构建的日常入口（K2）

- **大纲视图升级为编辑器**：就地增删改、拖拽移动（id 不变）、编辑别名/标签/优先级、
  节点状态徽标（骨架 / 草稿 / 已填 / 已复核）。
- **节点详情卡升级为可编辑**：现有只读卡（定义/公式/陷阱/考频）变为可编辑；
  **本节点题目**直接挂在详情下方（D17）：**图像题面卡**（V2 来源图管道，图片优先展示、
  文字摘要退居卡片页脚），带 对/错/错次 状态 chips 与「导入到此节点」入口；
  另有关联课时笔记列表。
- **课时笔记回流（逐步完善的主通道）**：确认一条课时笔记时选"归入哪个节点"
  （AI 默认建议，可改）→ 节点正文追加 `## 来自 <课时> 12:31 的笔记`。
  看课 → 记笔记 → 归档，知识库就这样一节一节长出来。
- **AI 补全此节**（按需，用户主动点）：单节点草稿生成进 `## AI 草稿（待确认）`，
  不碰用户已写内容。

---

## 4. 整理功能（K3）

- **AI 梳理本章**：读整章子节点 → 输出整理**报告**
  （疑似重复 / 过碎该并 / 过长该拆 / 缺失的中间节点 / 顺序问题）→
  每条建议附 **diff 预览**，用户逐条应用——AI 永远不直接改盘。
- **重复检测**：别名/标题相似度预筛（本地）+ LLM 复核（只对预筛命中跑）。
- **章节摘要（MOC）**：一键生成本章 `## 本章小结`（source=ai，可重生成）。
- **全库健康报告**：skeleton/draft/reviewed 占比、最久未动的章节、孤立节点（无题目无笔记）——
  给"该整理了"一个量化的触发时机。

---

## 5. 规划功能（D15：依赖 + 下一步推荐，不排日历）

- **priority（0–3）**：节点重要性，种子树来自 exam_weight，新树用户标或 AI 建议。
- **deps（前置依赖）**：AI 按学科常识建议依赖边，用户在编辑器里确认/修改；
  只用于排序推荐，不做强制校验（环检测只警告不阻断）。
- **掌握度回流**：节点关联题目的 FSRS 复习/练习数据现算聚合（口径同现有
  `masteryNowOf`），骨架节点掌握度为 null 而非 0。
- **「下一步学什么」推荐卡（学习台）**：
  `deps 拓扑可达（前置已掌握）∩ priority 降序 ∩ 掌握度低者优先 ∩ 关联课时进度`
  → 每天给出 1–3 个"今天值得啃的节点"，点过去直达节点详情。
- **不做**：日历排期、学习计划层（V3 既定范围外，StudyMate 借鉴项里已明确排除）。

## 6. 对现有系统的影响（迁移面清单）

| 现有件 | 处置 |
|---|---|
| `data/knowledge_points/*.json` | 降级为种子模板；importer 常驻（新装机可导入） |

| 标注引擎别名词典（recall） | 数据源换 `knowledge_index.aliases`（用户可加别名，召回立刻受益） |
| 录入页考点选择器 | 数据源同上（按名称**与别名**搜索的体验不变） |
| `mastery_service.problemsForKp` | 逻辑不变——id 保留了，存量 5000 题的关联全部有效 |
| 图谱视图 | 保留，数据源换 Markdown 树（768 节点规模已验证扛得住） |
| 错题本页（problems_page） | **取消顶级导航（D17）**：题目列表并入知识库（节点下方图像题卡 + 「未归类」组）；待复核/待补/错次变为知识库内筛选视图；`problems_index`/FTS5/详情抽屉/复习工作流等数据层原样复用 |
| 大纲视图 | 升级为编辑器（K2） |
| 画像「最薄弱考点」 | 口径不变（按节点聚合现算掌握度） |

## 7. 阶段（KB 轨道 K1–K3，与 V3_PLAN 的 P0–P5 并行推进）

| 阶段 | 内容 | 验收（量化） |
|---|---|---|
| **K1 数据层**（随 P0–P1） | Markdown 树加载器 + knowledge_index/FTS + 种子导入 | 768 考点导入后 **id 全保留、存量题目关联零丢失**（fixtures 钉死）；外部编辑器改文件后 App 重建索引正确；FTS 搜得到用户自己的话 |
| **K2 建库与编辑**（随 P2） | 建库向导（空白/拍目录/种子）+ 树编辑器 + 笔记回流 | 拍一页教材目录 → 三级骨架落盘（人工评可懂）；拖拽移动后 id 不变；笔记归档后节点正文出现对应小节 |
| **K3 整理与规划**（随 P3 之后） | AI 补全/梳理/查缺 + 下一步推荐 | 一章梳理报告可逐条应用（误报率人工评 ≤30%）；学习台出现"下一步学什么"且推荐理由可解释 |

每阶段同样要求：测试全绿、analyze 零输出。

参考图：`docs/design/ui/ui_knowledge.png`（树编辑器：状态徽标/优先级/依赖 chips/拖拽把手；
可编辑节点详情：惯例小节 + 「AI 草稿（待确认）」虚线框 + 关联题目与课时笔记；
顶部「下一步建议」横幅与全库健康度 chips），源稿与其他参考图同一管线（`ui_mockups.html`）。

## 8. 风险

| 风险 | 对策 |
|---|---|
| 768 节点树的编辑器/图谱性能 | 图谱已验证；编辑器列表虚拟滚动 |
| 用户手改文件破坏 frontmatter | 宽容解析 + index failures 如实上报（不静默丢节点） |
| AI 梳理误合并 | 一切改盘动作走 diff 预览 + 逐条确认 |
| 种子导入的双源过渡 | importer 原子化一次性切换；导入前 JSON、导入后 Markdown，不留中间态 |
| 骨架生成质量（冷门学科） | 骨架只是目录，错了在编辑器里改的成本极低；不追求一次成型 |
