# V3 方案：从「考研数学错题本」到「网课学习伴侣」

> 状态：方案定稿（2026-10-05），未开始实施。
> 前置：V2 优化已完成（FSRS-6 数值对齐、图片题面管道、复习页重做、组卷检索等，见 `docs/PROGRESS.md`）。
> 参考调研：`hazaban/StudyMate`（同赛道云端产品，结论：学其功能思路，不学其实现）。

---

## 0. 定位宣言

**旧定位**：把做错的题管起来，按遗忘曲线复习。

**新定位**：**跟着网课学，学完就能练。** App 陪伴用户看网课（桌面宠物伴学），
把课里的知识点自动总结成笔记，再从题库 + AI 自创题中生成匹配练习；
练错的题自然进入既有错题本与 FSRS 复习循环。

```
看网课 ──宠物伴学──► 课时笔记(知识点/公式, 挂考点徽标)
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
        题库匹配抽题            AI 自创题(待复核)
              └──────────┬──────────┘
                         ▼
                    课时练习(逐题作答)
                         │ 答错
                         ▼
              错题本 ──► FSRS-6 复习（V2 核心，原样保留）
```

**不动摇的纪律**（V3 全程遵守）：

1. **Markdown 事实源**：课时笔记、知识库节点与课程结构都是 Markdown 文件，SQLite 只做派生索引——
   和 `problems/*.md` 完全同构。
2. **本地优先 / 数据在用户手里**：截图处理完即焚，笔记落盘本地。
3. **BYOK**：全部 AI 调用走用户自己的智谱 Key，优先免费模型
   （`glm-4.6v-flash` 视觉、`glm-4.1v-thinking-flash`/文本免费档）。
4. **不内置版权题库**：练习 = 题库匹配 + AI 原创题 + 用户手动导入网上的题（三轨合规）。
5. **先量再改**：V3 新增功能都定义验收量化标准（见 §8 各阶段）。
6. FSRS 调度核心（已对齐 py-fsrs）**一行不改**。

**学科范围（D16）**：定位从考研数学 agent 扩展为**考研学习 / 日常学习 agent**——
伴学管道、课时笔记、知识库、练习生成均不限定数学，一个学科一棵知识树、
一个学科一组课程；数学知识树降级为内置种子模板之一。

## 2. 新信息架构（导航重组）

```
V2:  复习 | 错题本 | 知识库 | 录入 | 组卷 | 画像 | 对话 | 设置
V3:  学习台 | 网课 | 练习 | 知识库 | 复习 | 画像 | 设置        （7 项）
```

- **学习台（新首页）**：今日闭环四卡（看课/笔记/练习/复习，各带今日数字）+ 今天的节奏时间线 + 继续看课。
- **网课（新）**：课程 → 课时 → 课时笔记（时间戳流）。
- **练习（新，吸收组卷）**：入口一「课时练习」（新）、入口二「错题专练/真题全卷」（原组卷模板）。
- **知识库（吸收题库，D17）**：题目不再是顶级页——**题目挂在知识点下方以图像题面卡展示**；
  录入/导入入口在知识库页；未挂节点的题目进「未归类」组；"错题本"变成知识库内的筛选视图
  （按错次/待复核/待补筛，不再是独立页面）。参考图 `ui_knowledge.png`。
- **设置**：新增「网课伴学」分区（截图区域、频率、热键、B站登录态、隐私开关）。
- **桌面宠物**：独立悬浮窗，不属于导航——它是 App 的第二张脸（§5）。

改版原则：路由层重组，页面代码尽量平移（V2 的页面都是独立 widget，`adaptive_shell.dart`
的 `IndexedStack` 结构只改 tab 清单，焦点隔离机制原样生效）。

## 3. 数据模型 v3（全部增量，无迁移）

### 3.1 Markdown（事实源，新增两个目录）

```
<库根目录>/
├── problems/*.md            # V2 现状，不动
├── knowledge_points/*.json  # V2 现状，不动
└── courses/                 # V3 新增
    ├── <course-slug>/course.md
    └── <course-slug>/lessons/05-特征值与特征向量.md
```

`course.md` frontmatter：

```yaml
id: course-<slug>
title: 线性代数基础班
platform: bilibili | local | other
source_url: https://...
created_at: 2026-10-05
```

`lesson md` frontmatter + 正文约定：

```yaml
id: lesson-<course>-05
course_id: course-<slug>
idx: 5
title: 特征值与特征向量
duration_sec: 5400
status: watching | done
capture_region: "120,80,960,540"   # 该课时的截图区域，一次框选
```

```markdown
## 12:31 特征值的定义
- 老师强调：先写定义式再变形
- 公式：$A\mathbf{x}=\lambda\mathbf{x}$
- 关联考点：KP-2.1.3

## 18:05 相似对角化的条件
- …
```

约定：**一条 `## <mm:ss> <要点>` 就是一条笔记**。这个约定让笔记文件天然可解析、
可做 FTS、可按时间轴渲染，且用户拿任何 Markdown 编辑器都能手改——与错题文件同一哲学。

### 3.2 SQLite（Drift 派生索引）

- 新表 `courses_index` / `lessons_index`：镜像 `problems_index` 的建法
  （`index_builder.dart` 同构：全量重建 + idConflict 处置 + `selectOnly` 列裁剪）。
- 新 FTS5 外部内容表 `lesson_notes_fts`：按笔记条目建行（rowid 映射 lesson_id + 条目序号），
  外部内容表不重复存正文——V2 审计时已确认这是省内存的正确做法。
- `problems` frontmatter 增量字段：`lesson_id`（哪节课产出/关联）、`source` 枚举扩展
  `ai_generated` / `web_manual`。解析器对未知字段本来就宽容，旧文件零影响。
- 练习结果**复用 `papers` 表**：新模板 id `lesson_practice`，`PaperRequest` 增 `lessonId`
  与 `kpIds`。不为练习另起炉灶。

## 4. 模块一：网课伴学管道（截图轨 v1 + B站字幕轨 v2 增强）

### 4.1 截图轨道（v1，通用——任何播放器都行）

```
框选区域(每课时一次) ──► 定时(默认5min, 1–15可调) 或 全局热键「记一下」
      ──► 截屏(Isolate) ──► 存临时 jpg ──► glm-4.6v-flash「课堂笔记」prompt
      ──► RobustJson 结构化 {point, formula?, kp_candidates[], quote?}
      ──► 指纹去重(domain/fingerprint 同构) ──► 追加 lesson.md ──► 宠物气泡
```

设计要点：

- **区域框选**：透明遮罩窗口让用户框一次播放器位置，存进课时 frontmatter；之后全自动。
- **截屏实现**：`screen_capturer` 取全屏 → Dart `image` 包按区域裁剪。不追求抓指定窗口
  （PrintWindow 对硬件加速播放器经常拿到黑帧，全屏+裁剪更稳）。
- **频控**：默认 5 分钟/次 ≈ 每小时 12 次视觉调用，免费模型额度内；幻灯片没换时
  （截图感知哈希相同）直接跳过，不烧调用。
- **隐私**：截图只进临时目录，AI 返回后立即删除；设置里提供「纯手动模式」
  （仅热键触发）与「暂停伴学」开关。默认不截全屏、不存历史帧。
- **进度追踪（D10）**：截图里通常带播放器时间显示，视觉模型**顺带读出 `<mm:ss>`** 存进
  笔记——进度条、课时时间轴、学习台"继续看课 32:14/90:00"由此有数据，不多花调用；
  读不到时该条笔记不带时间戳，界面退化为"已记 N 条"。
- **单伴学会话（D12）**：一次只陪一门课；伴学中打开另一课时弹确认"暂停当前并切换"。
  截图/字幕频控按单会话设计。
- **prompt 纪律**：只记录课上讲的内容（定义/公式/口诀/易错点），不解题不扩展；
  输出必须是 JSON，沿用 `handwrite_check.dart` 的 RobustJson 解析模式。

### 4.2 B站字幕轨道（P4 增强）

- 用户粘贴 BV 号 → 拉取 CC 字幕（WBI 签名 + 用户自己的 SESSDATA，存 `meta_entries`）→
  按 N 分钟分窗送文本模型总结 → 生成带真实时间轴的笔记，与截图轨合并去重。
- 无 CC 字幕的课程自动回退截图轨。ASR（whisper.cpp）列为 P6 备选，不进本期。

### 4.3 笔记 → 考点关联

笔记的 `kp_candidates` 与知识库召回逻辑（别名匹配，V2 已有）取交集后挂 `关联考点`。
由此每条笔记获得两个出口：跳知识库看定义（`knowledge_leaf_detail` 已是公用组件）、
生成练习时按考点抽题。

## 5. 模块二：桌面宠物

**架构：主窗口是大脑，宠物窗口只是脸。** 截图、LLM、落盘全在主窗口进程；
宠物窗口只接收「状态 + 气泡文本」事件渲染。

- **窗口**：`desktop_multi_window` 开第二窗口 + `flutter_acrylic` 透明无边框置顶 +
  `window_manager`（主窗口关窗=缩托盘，伴学不中断）。
- **形象随服务商换皮（D7，2026-10-05 定）**：桌宠不是一只，是一套——**接入哪家 AI 服务商，
  桌宠就换哪只**。立绘与 `provider_registry` 预设一一对应（ChatGPT/Gemini/Grok/Claude/
  DeepSeek/通义/Kimi/豆包/智谱/MiniMax 十只），其中 **Grok、豆包、MiniMax 为 V3 新增预设**
  （三家都是 OpenAI 兼容协议，注册表加一行数据即可）。本地 Ollama / 自定义代理 /
  未配置 Key → 一律显示默认桌宠「小研」（智谱那只，应用主形象）。
- **形象**：Rive 状态机动画（`rive` 包，单文件、矢量、Windows 可用）。
  状态：`idle / watching / thinking / speaking / celebrate / sleepy`。
  美术工作量策略：**状态机与动作只做一套共享，十只换的是立绘贴图**；
  v1 先用静态立绘 + 呼吸/浮动位移动画，Rive 状态机先做默认「小研」一只，其余按皮肤跟进。
  参考立绘（AI 生成）已裁好：`docs/design/pet/providers/<id>.png` 十张透明底，
  裁剪管线 `tools/design/make_provider_pets.py`；Rive 正式资产据此人工重绘。
- **交互**：可拖拽；左键弹出当日摘要气泡；右键菜单（开始/暂停伴学、课堂问答、隐藏）。
  **课堂问答（D11）**：原对话页 Agent **全量搬家**——保留工具循环（查题库/知识库/笔记），
  并自动注入当前课时笔记上下文，能答"我这题为什么错"也能答"老师刚讲的特征值再讲一遍"；
  对话页据此按计划移除。
- **全局热键**：`hotkey_manager` 注册「记一下」（默认 `Ctrl+Alt+N`）；若注册失败
  （被占用）明确提示并在宠物菜单提供等价按钮——不静默降级。
- **崩溃隔离**：宠物窗口崩溃不得连坐主窗口（`desktop_multi_window` 独立 isolate 天然满足）；
  反之主窗口退出宠物随退。
- 默认桌宠暂定名「小研」（候选：墨墨 / 球球，P0 与作者确认，非阻塞）；
  **其余九只不单独起名，直接叫服务商名**（2026-10-05 定）。
  ⚠️ 早期单只选型记录：作者候选图中按手账风配色选中的「暖棕发抱书」角色，
  在确立换皮机制后归位为 **Claude 的皮肤**（`providers/claude.png`）；
  早期单选参考图 `pet_xiaoyan_reference.png` 保留作存档。

## 6. 模块三：练习生成（合规三轨）

入口：课时笔记页「生成本节练习」→ 弹窗选择题量与来源 → 组题 → 逐题作答 runner。

| 来源 | 机制 | 复用 |
|---|---|---|
| ① 题库匹配 | 笔记考点 + 笔记关键词 FTS → 从 `problems_index` 抽 5–10 题，优先错过的 | `PaperComposer`（新模板 `lesson_practice`）+ `problemSearchProvider` |
| ② AI 自创题 | 文本模型按课时笔记出 3–5 道**原创**题（题干/答案/解析/对应考点），**直接写成 Markdown 题文件**，`status: 待复核` | 现有录入→待复核工作流；prompt 明确「不得逐字改编任何教材/题库原文」 |
| ③ 手动导入 | 用户从网上看到的题截图/粘贴 → 走现有图像识别录入，`source: web_manual` | `entry_page` / `ingest` 管道原样复用 |

- **Runner**：逐题作答页（复用复习页的 `MathRendering` 渲染与双栏布局经验），
  交卷出小结（对错分布、错题去向）。结果写 `papers` 表。
- **判分 = 自主判分（D9）**：作答提交后亮参考答案与解析，**用户自评对/错**，
  选择、填空一视同仁——数学等价形式太多（1/2 = 0.5 = ½），机器判分 v1 不做
  （后续可作加速选项）；自评结果照常驱动错题联动与 FSRS。
- **自创题题型**：选择/填空为主；解答题以「题干 + 完整解析」的讲题卡出现，
  不出成判分题（GLM 出高质量解答题的可靠性存疑，且解答本就该自主判分）。
- **错题联动**：练习答错 → `wrong_count` +1（走与复习评分相同的 SQL 事务路径），
  该题自然出现在错题本与 FSRS 队列——**练习是错题本的上游进水口，这个闭环是 V3 的灵魂**。
- 合规说明：①是用户自己的库；②是原创生成物；③是用户主动录入。全程没有"平台搬运题库"。

## 7. 模块四：UI 全面重设计（温暖学习手账风）

### 7.1 设计语言

| Token | 值 | 说明 |
|---|---|---|
| 底色 | `#FAF7F2` 暖白 | 替换现在的冷灰白 |
| 卡面 | `#FFFFFF` | 柔和阴影（y 偏移大、模糊大、透明度低） |
| 主色 | 暖橙 `#E8833A` 系 | 行动按钮、进度、宠物主题色 |
| 辅色 | 墨绿（正确/完成）+ 柔红（错误/逾期） | 语义色沿用现有角色名替换色值 |
| 圆角 | 16（卡）/ 12（控件）/ 999（chip） | 现有 `AppRadius` 增 `rLg` |
| 字体 | 现有刻度不动 | `AppMathSizes` 等数学排版规范一律不碰 |

实施方式：**只改 token 值与少量组件样式，不改组件 API**——`app_theme.dart` 集中改，
全 App 自动跟随；这是 V1 就预留抽象的回报。

### 7.2 页面清单

- **学习台（新）**：四步闭环卡（看课/笔记/练习/复习，各带今日数字）+ 时间线
  （今天各课时：记了几条、练了几题）+ 继续看课大卡。
- **网课（新）**：课程列表 → 课时列表（进度）→ 课时笔记（时间戳流，每条挂考点徽标 +
  「生成本节练习」）。
- **练习（新）**：三个入口卡 + papers 历史列表（吸收组卷页）。
- **题库/知识库/复习/画像**：逻辑不动，token 换肤。
- **空状态**：统一宠物插画 + 一句人话（"还没有课程——去贴一节网课的链接吧"）。
- **宠物贯穿**：学习台角落常驻小宠物（同一 Rive 资产），里程碑时做表情。

## 8. 分阶段实施（含验收标准）

| 阶段 | 内容 | 验收（量化） |
|---|---|---|
| **P0 骨架与设计语言** | 导航重组（8→8）、token 换色、学习台静态版、App 显示名定稿、宠物名定稿 | 全部旧页面可达、现有测试全绿、`flutter analyze` 0 告警 |
| **P1 截图笔记管道** | 区域框选、定时/热键截图、GLM 笔记、去重、课时 Markdown、FTS、考点徽标；先在主窗口「网课」页呈现，宠物后置 | 播 10 分钟网课视频 → ≥3 条去重笔记落盘；人工评 10 条笔记，≥7 条"记得对"；主窗口作答无卡顿 |
| **P2 桌面宠物 MVP** | 第二窗口、六状态、气泡、拖拽、托盘、全局热键、崩溃隔离、**服务商换皮（含新增 Grok/豆包/MiniMax 预设）** | 主窗口缩托盘后伴学照常；连跑 30 分钟无泄漏；宠物崩溃主窗口存活；切换服务商后桌宠/侧栏/气泡形象同步更换 |
| **P3 练习生成** | 三轨组题、runner、papers 记录、错题联动、待复核自创题流 | 一节课 8 题（≥5 匹配 + ≥3 自创）完整作答；答错题出现在错题本且 wrong_count 正确 |
| **P4 B站字幕轨** | BV 导入、CC 拉取、分窗总结、与截图轨合并 | 有 CC 字幕的一节课全程笔记无需截图；时间轴与视频误差 ≤1 分钟 |
| **P5 换肤打磨** | 全页面手账风统一、空状态插画、Rive 正式资产、对话页移除、宠物贯穿 | 每页过视觉验收；删除对话页后全测试绿 |

依赖顺序：P0 → P1 → P2 → P3 → P4/P5（P4 可与 P3 并行）。**P1 是技术风险最高的一步**
（截屏、免费模型频控、结构化输出成功率），所以最先做、宠物放后面——宠物没有笔记管道
就是一张会动的贴纸。

**知识库轨道（K1–K3，详见 `docs/V3_KB_PLAN.md`）**与 P 轨并行：
K1 数据层（随 P0–P1：Markdown 树加载 + 种子导入，id 保留、存量关联零丢失）→
K2 建库与编辑（随 P2：建库向导 + 树编辑器 + 笔记回流）→
K3 整理与规划（随 P3 之后：AI 补全/梳理/查缺 + 「下一步学什么」推荐）。
每阶段验收见 KB 方案 §7。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 截屏拿到硬件加速黑帧 | 全屏+裁剪路线；P1 首日先做黑帧探测试验，不行则要求用户关闭播放器硬件加速（文档写明） |
| 免费模型频控/限流 | 频控节流 + 感知哈希跳帧 + 429 退避；超限时宠物明确说"笔记服务歇 X 分钟"，不静默 |
| 结构化笔记输出不稳 | RobustJson + 失败重试 1 次 + 仍失败则降级存原文截图文字（OCR 文本），绝不丢素材 |
| 多窗口/透明窗口兼容性 | `desktop_multi_window`+`flutter_acrylic` 是社区成熟组合；P2 首日做技术验证 spike，不达标则宠物退化为贴边悬浮条 |
| 版权 | §6 三轨机制；自创题 prompt 硬约束 + 待复核人审 |
| 范围膨胀 | 学习计划/番茄钟/游戏化农场（StudyMate 有）**明确不进 V3**；练习闭环跑通后再议 |

### 9.1 工程默认值（未逐条询问，按以下默认执行，随时可否决）

| # | 默认 | 理由 |
|---|---|---|
| G1 | 截图频率默认 5 分钟（1–15 可调），热键 `Ctrl+Alt+N`（被占用时提示换绑，不静默） | 免费档频控内；已定验收随实测调整 |

### 9.2 需作者配合的实测（不阻塞开发，P1/P2 期间穿插）

1. **免费模型频控实测**：用自己的 Key 连发截图调用，摸清 429 阈值 → 决定默认截图频率（G1）。
2. **黑帧探测**：用实际看的播放器（B 站网页全屏/网盘/本地播放器各测一次）验证截图是否黑帧。
3. **B 站 SESSDATA 导出**：P4 前从浏览器导出一次，验证字幕轨全流程。
4. **换宠验收**：P2 时切一家服务商（如 DeepSeek），确认悬浮窗/侧栏/气泡形象同步更换。
