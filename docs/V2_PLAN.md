# V2 优化计划（草案）

> 状态：**草案，待评审**。日期：2026-10-03。
> 依据：全库代码审查（覆盖 `app/lib` 全部 92 个源文件 + 工具链/CI，其中最严重的发现在源码与 py-fsrs 侧双重核实过）+ 8 条产品设想 + DeepTutor 等同类项目调研。
> 定位：V1 证明了「闭环能通」；V2 的主题是**把每一环做得对、做得好看**——先修正确性，再动界面。

## 0. 三条原则（继承 V1 纪律）

1. **先修对，再修美**。Phase 0 修正确性；Phase 1–4 重做的页面全部落在修好的地基上，避免在旧 bug 上盖新 UI。
2. **不静默降级**。所有新能力（图像录入、手写识别）失败时如实显示、给出出路，手动路径永远保留——「AI 挂了产品不能挂」。
3. **Markdown 事实源不动摇**。新增状态/报告类数据优先落 SQLite 冗余列或派生索引（与 `error_causes` 列同法），不写进 `.md`。

## 2. Phase 1：知识库重构（设想 #1 + #6 合并实施）

现状核实：考点详情页（`knowledge_leaf_detail.dart`）目前只有定义/公式/陷阱/考频/别名，**没有任何题目关联**；公式与正文混排在同一段 TextSpan 里——这是「太拥挤」的直接原因。

### 1.1 考点详情下方挂「该考点的题目」（同时实现设想 #6）

- 数据现成：`problems_index` 有 `primary_kp_id`（v4 schema 起还有 `error_causes` 列），一次索引查询即可，**不需要改 Markdown**。
- UI：定义/公式/陷阱之后新增「你的题目」一节——错题行 = 题面摘要 + 错因 chips + 掌握度% + 错次 + 样本量，点击进错题本详情抽屉。无题目时显示空槽（沿用画像「有多少数据说多少话」的口径，不画 0%）。
- 图谱/大纲节点上加**错题数徽标**：一眼看到哪个考点错得多。
- 错题行里直接展示错因（设想 #6 的落点），画像页保持现状不动。

### 1.2 知识总结排版重做

- 公式升级为**块级渲染**：每条公式独立成块、上下留白、字号走 `AppMathSizes` token。混排的 `latex_text_split` 摘分机制保留，但摘出的公式改为块级布局。
- 陷阱区改为独立样式的「提示卡」，与公式在视觉上分层。

### 1.3 真题举例（数据资产，需单独决策）

- 设想是「参考考研真题」。给每个热点单元配 1–2 道真题举例需要整理数据资产（knowledge JSON 加字段）。
- ⚠️ **与 README「不内置受版权题库」的纪律冲突**。折中方案：详情页先只放**题型与考频统计**（数据已有），原题走「用户自导入」；要不要内置真题举例留给作者拍板。此项不阻塞 1.1/1.2。

## 3. Phase 2：录入简化（设想 #4）+ 错题本整理（设想 #3）

### 2.1 录入 = 提交图像（默认路径）

- 现状：录入页是手输 LaTeX + 公式键盘，图像识别在批量导入页。设想把它们合流：**选图/粘贴/拖拽 → 视觉模型解析 → 逐题核对 → 入库**。
- 实现：从 `ingest_session` 抽出**单来源快捷路径**（不走批量会话与进度持久化），录入页默认展示图像提交区，核对 UI 复用 `ingest_page` 已有的逐题卡；手输 LaTeX 收进「高级模式」折叠，不删除。
- **免费模型预设**（2026-10 调研结论）：智谱开放平台三条免费视觉线全覆盖本场景——
  - **GLM-4.6V-Flash**：手写体/印刷体 OCR + MathVista/OCRBench 表现强 + 原生 function calling，**首选**；
  - GLM-4.1V-Thinking-Flash：题解、多步演绎与公式理解；
  - GLM-4V-Flash：基础图像理解（本项目最初 660 线代 201 题 0 失败的实测就是智谱免费视觉模型）。
  - 一个 Key 全覆盖，与 BYOK 架构零冲突。`provider_registry` 加「智谱免费档」预设并标注「免费」；设置页配 Key（P0-5 已铺垫）。

### 2.2 录入默认「没写过」（语义变化，需确认）

- 现状语义：录入即「错题」。改为状态生命周期 **未写过 → 做错 → 复习中 → 已掌握**：错次从 0 起，**首次复习评分才计错、才进 FSRS 队列**。
- 实现取最小改动：`user_problem_state` 无行 + `problems_index` 加 `status` 冗余列（与 `error_causes` 同法），Markdown 侧不落状态。
- 连带影响：新题不再自动出现在今日复习；错题本列表加状态筛选；「错题本」这个名字可能要跟着改成「题库」（纯文案决策）。

### 2.3 错题本行简化 + 渲染兜底

- 列表行只留：状态、知识点标签、错次（+缩略题面）；错因/星级/复习元数据收进详情抽屉——「标签怪怪的」的解法是**减少行内标签种类**，而不是再设计几种。
- 「一堆格式有问题」的根修：`MathRenderer` 加 **fail-soft**——单条公式解析失败时显示原文 + 灰点标记，不破坏整题版式；详情提供一键复制原文。顺手审计 1609 条语料里 18 条解析失败的真实分布，能修的修进 `latex_repair`。
- 顺带修：详情抽屉显示裸 id（`problems_page.dart:638`）、配图同步 stat + 无解码上限（`problem_images.dart:75`，`cacheWidth` 一行的事）。

## 4. Phase 3：复习页重做（设想 #2，最大单项）

### 3.1 布局：左题右析

- 宽屏（≥1200）双栏：**左题面、右解析**。题面 = `imagesPrimary ? 原图 : LaTeX`（字段与判定分支已存在于 `review_page.dart:504-530`，这次把它变成一等体验）；题面下方一行关键词 chips：**考点 + 错因 + 错次**（设想里「文本仅保留关键词，并提供标签」的落点）。解析默认隐藏，点击或空格展开；窄屏退化为上下布局（断点系统已有）。
- 顺带修：`_AllDoneView` 在 build 里造 Future（`review_page.dart:886`）、评分期间按钮无视觉禁用（`:81`）、排序比较器逐行解 JSON（`review_repository.dart:293`，与 `providers.dart:314` 刚修过的坑同款）、1165 行拆 `widgets/`。

### 3.2 手写答案识别（可选能力，默认关）

- 交互：复习卡加「拍照核对」——传手写解答图 → GLM-4.6V-Flash（支持手写体 OCR）→ 返回**要点命中清单**（不给总分）→ 三档打分仍由人确认。
- 契约写死：**FSRS 的输入必须是人类判断**，AI 只做参照——这条进提示词，与批量导入「防模型编造答案」同一纪律。
- 成本与可用性：每次调用进用量台账；失败如实报并直接退回手动打分；能力判定复用 `visionSupport` 三态闸门。

### 3.3 会话报告

- 写完全部卡片出报告：对/错分布、错因分布、最弱考点、与近 30 天对比、一键「按本次结果组卷」（衔接 Phase 4）。全部是本地聚合（数据都有），可导出 Markdown。
- 报告是**派生数据**，不落库、不写 .md，会话结束即生成、可另存。

## 5. Phase 4：组卷搜索（设想 #5）+ 对话（设想 #7）+ 设置（设想 #8）

### 4.1 组卷搜索

- **本地优先**：组卷页加检索框（FTS5 + 考点/难度/错次过滤，数据齐备），结果可「加入本卷」；组卷器支持「手工挑选 + 自动补位」混合模式，补位不满足时沿用现有的不静默降级提示。
- **扩充题库** = 把真题 PDF/截图走录入或批量导入进来（管线现成）。**不做**联网自动爬题：版权灰区、质量不可控，这条如实写进 UI 文案。

### 4.2 对话界面

参考 DeepTutor Chat：消息气泡重设计（用户/AI 视觉分层）、正文与公式统一行距、工具调用 trace 折叠卡更轻、欢迎页用画像数据驱动引导（「问我：哪块最弱？」可直接点）。顺手修 Enter 无 IME composing 守卫（`chat_page.dart:1776`，中文输入法确认候选词存在误发风险）。

### 4.3 设置控制面板

## 7. 风险与不做的事

- **存量 FSRS 数据**：P0-1/P0-2 修复后，已有卡片的 `fsrs_state` 是旧公式算的——**不迁移**（不可逆且无必要），只影响后续评分的增量；在 PROGRESS.md 记一笔即可。
- **真题版权**：不内置、不自动爬（README 纪律不变），1.3 与 4.1 的扩充都走用户自导入。
- **手写识别**是增强不是依赖：默认关、失败回退手动打分。
- **不做的**：移动端适配、云同步、第二科目——README 路线图 P2–P4 的位置不变。

## 8. 参考调研摘要

- **DeepTutor（HKUDS）**：agent-native 学习工作台（Chat / Knowledge Center / 三层 Memory / Quiz / Mastery Path）。对本项目可借鉴五点：
  1. Settings 做成控制面板：一区一卡 + 顶部状态条（→ 4.3）；
